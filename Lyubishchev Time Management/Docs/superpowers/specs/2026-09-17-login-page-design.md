# 首次登入頁前端設計

**日期：** 2026-09-17

**範圍：** ASP.NET Core MVC 的登入頁前端視覺、響應式版面與本地互動。
**不在範圍：** 登入 API、帳密驗證、JWT、Cookie、資料庫、註冊頁實作與忘記密碼。

## 目標

為首次進入產品的使用者提供一個快速、可信賴的登入入口。頁面採極簡專業 SaaS 風格，借鏡 Toggl Track 的清晰資訊層級與單一主行動按鈕，但維持單人、私密時間紀錄產品的定位。

## 選定的設計方向

採用「聚焦登入」的單欄置中版面，而非產品介紹雙欄或編輯式日誌版型。登入是唯一主要任務；新使用者透過表單下方的註冊文字連結繼續。

## 視覺與內容

- 全螢幕低對比暖灰白背景，中央白色登入卡。
- 卡片桌機寬度約 400px；細邊框、柔和圓角和極輕陰影。
- 頂端顯示 `LTM` 與輔助字 `TIME LOG`，不顯示一般網站導覽。
- 標題為「歡迎回來」，說明為「登入後，繼續如實記錄你的時間。」
- 欄位順序：電子郵件、密碼、登入。
- 登入按鈕採珊瑚紅、全寬、最小高度 44px，是頁面唯一的實色行動按鈕。
- 下方顯示「還沒有帳號？立即註冊」，僅「立即註冊」作為次要連結。
- 頁尾顯示「© 2026 LTM · 私人時間紀錄」。
- 不顯示社群登入、忘記密碼、行銷導覽、團隊或訂閱資訊。

## 響應式與無障礙

- 桌機：登入卡水平及垂直置中。
- 手機：自 320px 寬度起使用單欄，保留 20–24px 兩側邊距；品牌、標題、兩欄位與按鈕應優先出現在首屏。
- 每個輸入框均有持續可見的文字標籤；不可只用 placeholder 作為標示。
- Tab 順序為：電子郵件、密碼、密碼顯示切換、登入、註冊。
- focus 狀態採深灰藍邊框與清楚 ring，鍵盤使用者能辨識目前位置。
- 密碼預設遮蔽；顯示／隱藏操作要有可存取名稱與對應 ARIA 狀態。

## Razor 與靜態檔案邊界

登入頁不使用既有 `Views/Shared/_Layout.cshtml`，因為其包含首頁導覽與一般頁尾。改用獨立的簡化認證版型，將認證頁與已登入後的網站版型隔離。

| 檔案 | 責任 |
| --- | --- |
| `Views/Shared/_AuthLayout.cshtml` | 輸出認證頁文件骨架，設定 `zh-Hant`，載入 Bootstrap 與認證樣式，不含一般導覽。 |
| `Views/Account/Login.cshtml` | 呈現語意化表單、品牌、欄位、登入按鈕與註冊連結。後續可綁定既有 `LoginRequest`。 |
| `wwwroot/css/auth.css` | 定義登入頁專屬 token、版面、RWD、focus、hover、驗證與提交中樣式；不修改或污染 `site.css`。 |
| `wwwroot/js/auth.js` | 僅處理密碼可見性切換與提交中的視覺狀態；不發送 API 請求、不儲存資料。 |

Controller 在此階段只需要提供 View；任何登入驗證、帳號判斷或 JWT 發行仍屬後續 `AuthService` 與安全層的責任。

## 前端狀態

| 狀態 | 呈現 |
| --- | --- |
| 初始 | 主按鈕可用，所有欄位標籤與註冊連結清楚可見。 |
| Focus | 欄位呈現深灰藍邊框與可見 focus ring。 |
| 必填或格式不正確 | 欄位下方呈現繁體中文短訊息，不清除使用者已輸入內容。 |
| 提交中 | 按鈕文字改為「登入中…」，並禁止重複提交。此版本只模擬此視覺狀態。 |
| 伺服器登入失敗預留 | 表單上方保留通用警示區，文案為「電子郵件或密碼不正確。」未來不得藉此透露帳號是否存在。 |

## 驗收

1. 於 320px、768px 與一般桌機寬度手動檢查，表單可讀且可操作。
2. 使用鍵盤完成 Tab 導覽，focus 清晰且順序正確。
3. 密碼顯示／隱藏不會清除已輸入內容。
4. 前端必填及 email 格式提示不會清除欄位內容。
5. 提交中不可重複按下登入按鈕。
6. 靜態前端不包含 API 呼叫、JWT、帳號資訊或任何敏感資料。

## 設計檢查

- 沒有 TBD、TODO 或未決占位需求。
- 單欄登入、獨立認證版型、前端限定範圍與驗收條件一致。
- 設計限定為單一登入頁，沒有擴張到註冊流程、帳號復原或其他 V1 非目標功能。
