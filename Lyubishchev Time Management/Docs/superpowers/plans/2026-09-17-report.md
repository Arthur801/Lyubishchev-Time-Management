# Report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供本月預設的 Category 圓餅圖與 Tag 長條圖報表，兩者依帳號時區和共用 aggregation 規則運作。

**Architecture:** ReportService 只轉接 range 與 TimeAggregationService 結果至兩個 report response；Report API 保持 thin；report.js 平行取得、分別渲染 Category/Tag。無圖表第三方依賴。

**Tech Stack:** ASP.NET Core MVC、EF Core、TimeAggregationService、Razor、原生 JavaScript/CSS、SQLite xUnit tests。

- [ ] **Step 2: 實作 aggregation consumer**

### Task 2: API 與受保護頁面

- [ ] **Step 1: 實作 endpoint mapping**

```csharp
[Authorize, Route("api/reports")]
public sealed class ReportApiController(ReportService service, CurrentUserService currentUser) : ControllerBase
{
    [HttpGet("category")] public async Task<IActionResult> Category([FromQuery] ReportRequest request, CancellationToken ct) => Map(await service.GetCategoryAsync(currentUser.GetRequiredUserId(), request.Preset, request.StartDate, request.EndDate, ct));
    [HttpGet("tag")] public async Task<IActionResult> Tag([FromQuery] ReportRequest request, CancellationToken ct) => Map(await service.GetTagAsync(currentUser.GetRequiredUserId(), request.Preset, request.StartDate, request.EndDate, ct));
}
```

## Consistency check

- Report consumes TimeAggregationService and User timezone rather than duplicating DST, interval or aggregation logic.
- Category is a pie only; Tag is a bar only because its additive totals can exceed tracked time.
- Dashboard, Calendar and CSV remain outside this plan.
